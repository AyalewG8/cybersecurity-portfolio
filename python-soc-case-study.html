Challenge

Detect one incident across noisy telemetry.

The dataset mixes routine administrator logins, user mistakes, normal web traffic, and large software downloads with a password spray, compromised login, persistence, regular beaconing, and outbound uploads.

My Role

Build a repeatable analyst workflow.

I used Python to generate deterministic evidence, parse two log formats, correlate events by identity, source, host, destination, and time, rank findings, and test both true-positive and false-positive behavior.

Detection Pipeline

Five analytics turn raw logs into findings

Password Spray

Find one source failing against many distinct accounts inside a short window.

Compromised Login

Correlate later successful authentication from the spray source.

Persistence

Detect account creation and privileged writes to sudoers or SSH keys.

Beaconing

Measure request timing and identify a stable median interval despite jitter.

Large Upload

Aggregate outbound bytes by source and destination within a time window.

Reproducible Analysis

The triage command also supports JSON output for machine-readable findings. Exit code 1 intentionally signals that critical findings are present, allowing the tool to act as a pipeline gate.

Positive coverage

Tests validate parsing, spray correlation, persistence, timing analysis, upload aggregation, JSON output, and dataset figures.

False-positive control

Tests reject one-account brute force, low-volume failures, irregular traffic, page-load bursts, small uploads, large downloads, and routine sudo activity.

Incident Decision

Contain the endpoint and identities; preserve evidence

Recommended response: Isolate the affected workstation, disable compromised and persistence accounts, revoke sessions and keys, block confirmed indicators, preserve authentication, proxy, endpoint, and memory evidence, then scope and escalate through incident response.
